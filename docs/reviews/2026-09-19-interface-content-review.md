## TL;DR

ปรับภาษาที่ใช้บนหน้าจอให้เป็นทางการ เป็นกันเอง และกระชับ โดยตรวจทั้งข้อความ
ตั้งต้นและข้อความที่แสดงเมื่อข้อมูลสดเข้ามา ไม่เปลี่ยนคะแนน เกณฑ์ตัดสิน
สิทธิ์ผู้ใช้งาน หรือนโยบายความปลอดภัย

ระบบยังมีสองรูปแบบ: **Overnight Recovery ใช้ Sleep Score** และ
**Nap & Refresh ใช้ Recovery Score** ไม่เพิ่ม Restore Score เป็นคะแนนที่สาม

## ขอบเขตที่ปรับ

| หน้าเข้าสู่ระบบและข้อมูลพื้นฐาน | ข้อความกรอกข้อมูลและแจ้งข้อผิดพลาดใช้ภาษาไทย ระบุสิ่งที่ทำต่อได้ ไม่สันนิษฐานว่า server กำลังเริ่มใหม่เมื่อพบข้อผิดพลาดทั่วไป |
| เมนูและส่วนหัว | ใช้ “ภาพรวมการพัก”, “ควบคุมอุปกรณ์”, “ประวัติการใช้งาน”, “ติดตามระบบ” และ “ทดสอบอุปกรณ์” ให้สอดคล้องกัน |
| Dashboard | อธิบายช่วงเวลาพักอ้างอิงให้เข้าใจง่าย แยกค่าปัจจุบัน ค่าล่าสุด และข้อมูลที่ยังไม่พร้อม; ส่วน Admin ระบุรอยืนยัน 60–120 วินาทีให้ครอบคลุม N2 |
| Control | ปุ่มเล่นซ้ำ/ตามคิวและคำอธิบายกลิ่นใช้ภาษาเดียวกัน สถานะแอร์ระบุว่าเป็นคำสั่งล่าสุด ไม่ใช่การวัดสถานะจริง |
| Monitor | ชื่อหมวดและคำอธิบายเซนเซอร์เป็นภาษาไทย คง reason code, DSP และรายละเอียดที่จำเป็นต่อการตรวจระบบ |
| Smart Ear | ใช้ “เหตุการณ์เสียงระหว่างพัก”; นอกการพักยังแสดงสดโดยไม่บันทึก ไม่เรียกสัญญาณคล้ายกรนว่าเป็นการกรนที่ยืนยันแล้ว |
| ประวัติการใช้งาน | ใช้ “การพัก” ในหัวข้อและสถานะ; จำนวนรายการที่ไม่มีข้อมูลเซนเซอร์ระบุว่า “ไม่มีข้อมูล” ไม่ใช้ “ไม่ครบ” แทนกัน |
| จบการพักและ QR | ปุ่ม “จบการพัก”; “บันทึกผลลงโทรศัพท์”; “ซ่อนผลและกลับหน้าเข้าสู่ระบบ” โดยไม่สื่อว่าได้ลบรายงาน |
| ผลสรุปและ API | ใช้ข้อความจากชุดกลาง; ข้อมูลย้อนหลังที่ไม่พอใช้ “ข้อมูลประกอบจำกัด” หรือ “ข้อมูลส่วนนี้ยังไม่เพียงพอสำหรับสรุปผล” ไม่สื่อว่ายังรอเก็บเพิ่ม |

## ความคลาดเคลื่อนที่แก้ตามโค้ดจริง

1. กลิ่น/ไอน้ำ: ข้อความเดิม 1 วินาที แก้เป็น 5 วินาทีให้ตรงกับค่าเริ่มต้น
   `AROMA_STEAM_PULSE_SECONDS` และปุ่มใน runtime ไม่เปลี่ยนเวลาสั่งงาน
   หากเครื่องใดตั้งค่านี้ต่างจาก 5 วินาที ต้องปรับข้อความให้ตรงกับ configuration นั้น
2. แอร์: Control Hub ยืนยันคำสั่ง IR ไม่ได้ยืนยันการทำความเย็นจริง
   ข้อความจึงใช้ “คำสั่งเปิดแอร์/ปิดแอร์”; หากไม่ทราบค่าให้แสดง “ยังไม่ทราบคำสั่งล่าสุด”
   ไม่แปลงข้อความเป็น “ปิดแอร์” และระบุค่าอุณหภูมิที่วัดว่าเป็นอุณหภูมิภายในตู้
3. BCG flag 5: ใช้ “สัญญาณคล้ายกรน” ไม่ใช่ “มีเสียงกรน”
   ไม่เปลี่ยนรหัส flag หรือผลการจำแนก
4. รอยืนยัน Sleep State: หัวข้อเดิมระบุ 60 วินาทีทั้งหมด แต่รายละเอียดมี N2
   120 วินาที จึงปรับหัวข้อเป็น 60–120 วินาที โดยไม่เปลี่ยน estimator
5. ค่าที่ไม่อัปเดต: ไม่เหมารวมว่าเกิดจาก restart ใช้ “ค่าล่าสุดที่ได้รับ · รอข้อมูลใหม่”
   ส่วนข้อความ restart ที่มี restored flag จริงยังแสดงได้

## สิ่งที่คงเดิม

- คะแนน สูตร ระยะเวลาเป้าหมาย เกณฑ์ Sensor และ Sleep State
- Raw file, ผลย้อนหลัง และ Audit trail; ไม่ต้อง Rerun เพื่อเปลี่ยนข้อความ
- Route, stable key, enum, payload, สิทธิ์ User/Admin และการซ่อนข้อมูลส่วนตัว
- คำเตือนฉุกเฉิน การออกจากตู้และแจ้งทีมงาน รวมถึงการยืนยันคำสั่งที่มีผลต่อผู้ใช้
- Smart Ear เป็นป้ายทดลองสำหรับผู้ดูแล ไม่ใช่ผลวินิจฉัยหรือผลจำแนกที่รับรองแล้ว
- คำถามความรู้สึกหลังพักยังเป็นข้อเสนอ ไม่สร้างคำตอบอัตโนมัติหรือเพิ่มแบบสอบถามในรอบนี้
